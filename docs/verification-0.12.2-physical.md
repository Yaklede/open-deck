# Open Deck 0.12.2 실기기 연결 검증

Galaxy Tab S7(`SM-T870`)과 Mac에 **Open Deck 0.12.2 / build 23**을 설치하고 후속 실기기 검증을 진행했다. 앱 소스는 `10436bd15660b6d7e6fbef8364069983a688ffd5`이며 기존 [v0.12.2 공개 릴리즈](https://github.com/Yaklede/open-deck/releases/tag/v0.12.2)와 같다. 이 검사를 위한 앱 코드 변경이나 설치 파일 재빌드는 없다.

[기존 코드 검증 보고서](verification-0.12.2.md)는 설치 전 수행한 검사의 범위로 보존한다. 이 문서는 그 이후의 실기기 결과를 별도로 기록하며, [구조화된 증거](evidence/0.12.2-physical.json)에 판정과 원본 해시를 남긴다. **별도 안정 구간 5분은 통과했으며 추가 태블릿 재시작 검사는 사용자 요청으로 미뤘다.**

## 설치와 보존

실기기에 설치된 APK가 공개 릴리즈 파일과 일치하고 기존 Android 서명자를 유지하는지 확인했다. 설치된 Mac의 build-info도 공개 릴리즈와 일치한다. 업데이트 전 안전 백업을 생성했고, 설치 후와 최종 확인에서 덱·페어링 identity·호스트의 공유 기기 설정·페어링된 기기 수가 보존됐다. Android 로컬 연결 모드는 아래 최종 상태에 별도로 기록한다.

태블릿 앱은 **Wi-Fi 전용 모드**로 검사했다. 설치 시 USB 제어 기기가 감지됐지만 추가 재시작 검사 시점에는 사용할 수 없었다. 분리 시점을 관측하지 않았으므로 **5분 내내 USB가 연결됐거나, USB가 분리된 상태로 5분을 검사했다고 주장하지 않는다.** 원본 sampler의 `usbControlCablePresent: true`는 초기 조건을 기록한 필드이며 연속 측정값이 아니다. 다른 기기의 USB stream은 판정에서 제외하고 대상 태블릿의 Wi-Fi stream과 online 상태만 확인했다. 매크로 실행이나 OS 전체 재부팅은 하지 않았다.

## 최초 5분: 앱 재시작 구간 포함

앱 강제 종료·재실행 직후 수집을 시작한 최초 관측은 **끊김 0회 기준을 충족하지 못했다.** 이 결과를 이후 안정 구간으로 대체하거나 숨기지 않는다.

| 항목 | 결과 |
| --- | --- |
| 관측 기간·표본 수 | 300.01초·301개, 약 1초 간격 |
| 최대 관측 간격 | 1.377초 |
| offline 표본 | **1개**, 시작 후 1.009초 |
| 대상 Wi-Fi stream이 정확히 1개가 아닌 표본 | 1개 |
| 대상 USB 데이터 stream 표본 | 0개 |
| 조회 API 오류 | 0개 |
| Wi-Fi stream 종료 로그 | `client_closed` 2개 |

초기 online 상태는 시작 후 0.016초에 true, 1.009초에 false, 2.006초와 3.009초에 다시 true였다. 실행 기록과 대조한 두 종료 로그는 시작 시 수행한 앱 강제 종료·재실행 및 초기 `onResume` 전이와 겹쳤고, 그 뒤 이 관측창에서 추가 종료 로그는 없었다. 해당 실행 맥락은 기록하되 최초 구간을 무중단 통과로 판정하지 않는다.

## 별도 안정 구간 5분

시작 구간 이후 대상 태블릿이 Wi-Fi로 online인 표본을 10회 연속 확인한 뒤, 별도의 5분 수집을 수행했다. 이 단계는 **통과**했으며 최초 구간과 독립된 결과다.

| 최대 관측 간격 | 1.184초 |
| offline 표본 | **0개** |
| 대상 Wi-Fi stream이 정확히 1개가 아닌 표본 | 0개 |

## 재시작 검사와 최종 상태

별도 태블릿 재시작 검사는 첫 ADB 명령에서 USB 제어 기기를 찾지 못해 **실제 재시작 전에 중단**됐다. 무선 ADB 검색 결과도 없었고 기존 무선 ADB 주소 연결은 거절됐다. 이후 사용자가 재시작 검사를 나중에 하겠다고 요청해 `deferred_by_user`로 종료했다. 이를 앱 재시작 실패나 검증 통과로 판정하지 않는다. Mac 앱은 설치 과정에서 재시작했지만 별도의 추가 재시작 검사는 수행하지 않았다.

최종 호스트 확인에서 대상 태블릿은 online이며 Wi-Fi stream 1개, USB 데이터 stream 0개였다. 덱·페어링·공유 기기 설정과 페어링 기기 수는 원본 그대로였다. **연결 모드는 현재 Wi-Fi 전용이다.** USB 제어를 사용할 수 없고 추가 태블릿 작업을 미뤘으므로 원래의 자동 모드로 복원하지 못했다.

## 연결과 데이터 상태의 구분

검사 시 Grafana 프로젝트 상태 4개가 ready였고 Mac 시스템 상태는 connected였다. Jimin OS는 별도로 stale / `backend_retrying` 상태였으며, 로컬 bridge에는 연결되고 마지막 성공 데이터는 보존됐다. 태블릿 연결이 살아 있다는 사실이 모든 데이터 제공자의 최신 수집 성공을 뜻하지는 않는다.

Jimin OS 읽기 전용 진단에서는 설정 소스의 주소가 NXDOMAIN으로 응답하고 비교용 DNS 조회는 성공했다. 백엔드 로그에는 network / HTTP 0 실패가 보였다. 그러나 **설치 앱의 실제 runtime origin과 각 요청의 DNS 실패 원인은 확인하지 못했으므로 DNS를 확정 원인으로 단정하지 않는다.** 이 관찰을 태블릿 Wi-Fi 연결 장애의 증거로 사용하지 않는다. 주소·로그 원문은 공개하지 않는다.

## 검증 범위

1초 표본과 호스트 종료 로그의 제한된 관측이며 모든 순간의 무중단 연결, 지연시간, 장기간 안정성을 보장하지 않는다. 실기기 전체 재부팅, 잠금 해제, 통제된 USB 케이블 분리나 네트워크 변경은 이번 검사 범위가 아니다.

초기 구간의 기준 불충족, 별도 안정 구간의 통과, 사용자 요청으로 미룬 재시작 검사와 복원하지 못한 연결 모드를 구분해 기록했다. 원본 로그·캡처, PIN·토큰, 사적 주소, 기기 식별자, 실제 업무 지표와 절대 수집 시각은 공개하지 않는다.
