# Open Deck 0.10.2 — Wi-Fi 전용 실기기 설정 검증

Galaxy Tab S7(`SM-T870`)과 Mac에서 일반 설정 29개와 이름의 Wi-Fi 양방향 반영·재시작 유지, 별도 보안 설정 검사와 원래 값 복원을 확인했다. USB 활성화 복원, 임시 무선 ADB 정리, 공개 설치 파일 대조와 최종 데이터 보존까지 통과했다. 보안 설정은 별도 격리 환경에서 확인했으며 운영 연결의 보안 정책은 유지했다.

## 검증 환경과 연결 경로

- 앱: 기존 배포된 `0.10.2`·build `18`, 소스 [452b0cf](https://github.com/Yaklede/open-deck/commit/452b0cfbaa0f22dc93fd23306c08f501f326ae9c).
- 실기기의 물리 USB 케이블 분리는 사용자가 확인했다.
- 운영 앱 데이터는 실제 LAN의 HTTPS `8841` 연결로 전달했다. Mac의 Open Deck USB 연결 기능은 검사 중 일시적으로 꺼 두었으며, 앱 연결용 `8840` ADB reverse를 사용하지 않았다.
- 무선 ADB `37553`은 화면 조작·캡처와 앱 재시작을 위한 제어 경로였다. Open Deck 앱 데이터가 전달되는 HTTPS 경로와 구분한다. 검사 후 임시 무선 디버깅을 종료하고 원래 USB 디버깅 모드로 복원했다.
- 보안 설정 1개는 별도 APK·합성 호스트의 HTTPS `18842`에서 검사했다. 초기 등록에는 무선 ADB의 `18840` 터널을 일시 사용했으나 등록 후 제거했고, 모든 판정은 HTTPS `18842` 직접 연결에서 수행했다. 운영 보안 설정은 켜지 않았다.
- 앱 소스와 배포 파일의 변경은 없다. 기존 `0.10.2`의 검증 작업이며 새 버전이나 릴리즈 재발행은 하지 않았다.

API 저장값은 네이티브 화면의 표시값과 별도 증거다. 무선 ADB로 앱을 제어했다는 사실만으로 Open Deck 데이터의 Wi-Fi 전달을 입증하지 않으며, 실제 호스트 연결 기록과 함께 판정한다.

연결 기록은 총 2,634개 표본 중 Wi-Fi 2,399개, USB 0개를 확인했다. 호스트 응답 없음 225개와 호스트는 응답하지만 대상 스트림이 없는 표본 10개도 공백으로 기록했다. 연결 공백은 5개 구간이며 원인은 분류하지 않았다. 표본 수집 공백은 없었지만, 이를 표본 사이의 무중단 연결이나 지연시간 측정으로 해석하지 않는다.

보안 검사는 운영 Mac 앱 셸이 아닌 같은 설정 UI를 사용하는 별도 네이티브 WKWebView와 검증 APK에서 수행했다. 최초 실기기 연결 화면에서도 HTTPS `18842`·Wi-Fi 전용 경로의 5개 조건을 확인했다. 검증 APK와 운영 APK의 관련 보안 구현 대조 및 원본 캡처 해시는 같은 보안 기록에 포함했다. 운영 보안 허용값은 계속 꺼져 있었다.

## 복원과 최종 확인

검증 전 기준 파일에 저장된 대상 태블릿의 **원래 이름과 정확한 설정 30개**가 양쪽 네이티브 화면에 복원되었음을 확인했다. 시스템 언어·시스템 테마·밝기 기본값·화면 보호 끔·자동 아이콘 해상도·기본 프로필과 시작 페이지의 표시도 포함한다. 이전 실기기 검사에서 사용한 기본값·6개 덮어쓰기 방식과 혼동하지 않는다. 무선 ADB 정리 후 Mac preferences의 `usb.enabled`만 원래의 `true`로 부분 복원했으며, 다른 항목을 덮어쓰지 않은 채 전체 preferences와 저장파일이 기준값과 같음을 확인했다.

운영 덱·다른 페어링 기기 3대의 이름과 설정·대상 페어링의 보존, 저장파일 및 반복 읽기 일치를 확인했다. 실행 담당자는 별도로 임시 무선 ADB TCP 포트를 닫고 제어 연결을 끊은 뒤 원래 USB 디버깅 모드로 되돌렸다. 물리 USB 케이블이 없는 상태에서 운영 앱의 HTTPS Wi-Fi 연결은 계속 온라인이었으며, Mac USB 활성화를 원래대로 복원한 뒤에도 Wi-Fi 연결이 유지되었다. 복원 도구가 ADB나 태블릿의 로컬 연결 방식을 변경한 것으로 기록하지 않는다.

[최종 정리·배포 대조 기록](evidence/0.10.2/physical-wifi-cleanup-and-release.json)에서 검증 APK 제거, 합성 호스트·포트 종료, 별도 Mac 검증 창 종료를 확인했다. 실기기의 운영 앱은 연결 방식을 `auto`로 복원하고 앱을 다시 연 뒤 원래 설정과 온라인 상태를 확인했다. 설치된 APK의 SHA-256은 공개 [v0.10.2 릴리즈](https://github.com/Yaklede/open-deck/releases/tag/v0.10.2)의 APK와 정확히 같으며, 설치된 Mac 앱도 `0.10.2`·build `18`이다.

## 해석 범위와 공개 정보

이 검증의 대상은 설정 컨트롤 값, 저장, 실제 Wi-Fi 연결을 통한 전달과 앱 재시작 복원이다. 운영체제 재부팅, 실제 진동 강도·패널 밝기·출력 음량 측정, 모든 설정 조합, 모든 업무 알림의 도착을 검증한 결과로 확대하지 않는다.

보안 허용값의 저장·동기화를 TLS 연결에서 확인하더라도 실제 평문 HTTP Wi-Fi 트래픽을 시험한 것은 아니다. 공개 증거에는 비밀값·인증 정보·기기 UUID·원래 이름·사용자 프로필 및 페이지 이름·LAN 주소를 노출하지 않는다.
