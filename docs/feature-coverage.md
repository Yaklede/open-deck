## Plugin compatibility evidence

Open Deck's own adapter was connected to the official Sample Weather executable built with **MacroDeck.Plugin.Hosting 3.0.0-beta.18**. `set-alert-threshold` changed the plugin's own `alert-threshold-celsius` reading from 30 to 23; Open Deck retrieved that value over the public capability protocol. Unsupported weather/config-flow/localization capabilities were rejected. This proves the limited action/read-variable path, not the whole store. The sample produces synthetic weather and is not installed as a real weather integration.

The adapter binds only to an ephemeral loopback port. Each managed launch has a new random secret and session token. Plugin paths are registered explicitly; entrypoints must resolve inside the registered directory. Plugins run with the logged-in user's permissions and are not sandboxed. Only register trusted self-contained `osx-arm64` packages. Open Deck does not install a .NET runtime for framework-dependent plugins. Raw plugin output is not forwarded to tablets.

The supported host callback subset is `config/entries` (the actual empty configured-entry list) and `variables/refresh`. Other callbacks return `CAPABILITY_UNSUPPORTED`; no fabricated data is returned. Thus even an action-only plugin may fail if it requires additional callbacks. Configuration-dependent plugins need future adapter work.

The [plugin inventory](plugin-inventory.md) lists all 36 registry entries assessed on 2026-10-21, separating feasibility from verified compatibility.
