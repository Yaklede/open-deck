# Open Deck 0.12.2 연결 안정성 코드 검증

소스 `10436bd15660b6d7e6fbef8364069983a688ffd5`의 Open Deck **0.12.2 / build 23** 재연결·SSE 전송 변경을 소스 분석, 순수 Java 검사, 격리한 실제 HTTP 호스트와 TCP 클라이언트로 검증했다. [구조화된 증거](evidence/0.12.2-code.json)에 판정과 비공개 원본 해시를 기록한다. **실기기·에뮬레이터 검증은 하지 않았고 운영 호스트·설정·네트워크는 조작하지 않았다.** 최종 릴리즈 소스와 설치 파일 확인은 아래 배포 항목에서 별도로 기록한다.

## 장애 원인과 확인 범위

기존 소스에는 정상 스트림을 무조건 5초마다 종료하는 타이머가 없었다. 다만 HTTP 200 헤더만 받아도 재시도 대기와 자동 검색 실패 이력을 초기화했다. **연결 시작 4초 후 EOF를 받는다는 조건**이면, 연결 4초와 초기화된 재시도 1초가 합쳐져 약 5초 반복이 가능했다. 이는 가상 시계로 소스를 따라 계산한 조건부 시나리오이며 실제 호스트가 4초마다 EOF를 보냈다는 측정 결과가 아니다.

기존 Android read timeout은 6초, snapshot freshness·watchdog는 8초였다. 새 snapshot이 잠시 지연되면 freshness 기준 전에 소켓 timeout이 발생할 수 있었고, heartbeat만 받는 경우에도 snapshot 기반 watchdog이 연결을 닫을 수 있었다. 이 코드 경로를 확인했으나 **사용자가 겪은 실제 장애의 단일 원인은 확정하지 않는다.**

호스트에서는 전송 대기 바이트가 256,000을 초과하면 다음 broadcast에서 즉시 연결을 종료했다. 실제 `createHost`와 합성 Grafana 데이터로 아래 결함을 재현했다.

| 격리 조건 | snapshot JSON 크기 | 수정 전 서버 강제 종료 | 수정 후 |
| --- | ---: | ---: | --- |
| DB 노드 2개·프로젝트 1개, 정상 수신·연속 갱신 | 14,445 bytes | 0회 | 0회·연결 유지 |
| DB 노드 64개·프로젝트 3개, 정상 수신·연속 갱신 | 491,950 bytes | 1회 | 0회·연결 유지 |
| 같은 대형 데이터, 수신 일시 중단·주기 갱신 | 491,950 bytes | 1회 | 0회·연결 유지 |

수정 전후 입력은 동일하고 각 시계열은 합성 표본 60개다. TCP 수신 일시 중단은 최대 8회의 1초 간격 갱신으로 검사했다. 15초 이상 지속되는 정체는 별도 통합 검사에서 종료와 진단 로그를 확인했다. 운영 Grafana의 실제 데이터 크기나 실제 Wi-Fi 상태를 측정한 시험은 아니다.

## 변경된 연결 정책

- 호스트는 `write(false)` 이후 미전송 snapshot을 최신 1개로 교체하며, `drain` 뒤 전송한다. 큰 정상 payload만으로 연결을 종료하지 않는다.
- config·기기 설정 revision은 실제 write가 수용된 뒤 갱신한다. 대기 중 설정을 여러 번 바꿔도 최신 설정을 전달하며, 전송 직전에 권한을 다시 확인한다.
- snapshot 생성과 별도로 2초마다 SSE heartbeat를 보낸다. 전송이 막힌 동안 heartbeat를 추가 적재하지 않고, 15초 지속 정체일 때만 종료 원인을 기록한다.
- Android는 transport 생존과 데이터 freshness를 구분한다. read timeout·무응답 watchdog은 20초이며, 실제 snapshot freshness는 기존 8초를 유지한다. heartbeat가 지표 시각을 최신으로 바꾸지 않는다.
- 유효 snapshot 2개 이상을 받고 첫 snapshot 이후 10초 이상 안정적으로 유지해야 재시도 이력을 초기화한다. 짧은 연결 실패는 1→2→4→8→15초 대기로 제한한다.
- 자동 모드의 Wi-Fi 전환은 검증한 후보 주소와 유효 snapshot을 확인하며, 전환 재시도에는 30초 간격을 적용한다. 이전 연결의 늦은 응답이 새 연결 상태를 덮어쓰지 않도록 검사한다.

권한이 철회된 대기 데이터는 폐기한다. 정상 writable 스트림은 정상 종료하고, 전송이 막힌 스트림은 즉시 중단한다. 다른 기기를 철회해도 정상 클라이언트 연결은 유지되는지 확인했다. 인증서 pin 검증과 기존 기기 인증을 완화하지 않는다.

| 검사 | 결과 |

| 전체 호스트 테스트, `--test-concurrency=1` | **261/261 통과** |

| Java 정책·파서 검사 | **196/196 통과** |
| 문자열·번역 검사 | **22/22 통과**, 1,558개 문자열·19개 언어, 누락·placeholder 오류 0건 |
| Android compile·lint | 통과, 오류 0건·fatal 0건·경고 22건 |

Java 196개는 `HostRecoveryPolicy` 46개, `StreamConnectionPolicy` 86개, `SseLineReader` 49개, `DataFreshness` 15개다. 실제 Android 앱의 소켓·NSD·UI 동작을 실행한 수치로 해석하지 않는다.

새 호스트 검사는 독립 heartbeat, 큰 정상 프레임, 실제 TCP pause/drain, config·기기·관리자 기기 목록의 최신 revision 전달, 대기 중 권한 철회, 15초 정체 종료와 비밀값 없는 원인 로그, 타이머·리스너 정리를 포함한다. 순수 정책 검사와 실제 격리 TCP 검사를 구분해 기록했다.

## 배포 확인

[v0.12.2 릴리즈](https://github.com/Yaklede/open-deck/releases/tag/v0.12.2)를 최신 정식 릴리즈로 게시했다. 앱 소스 및 태그는 `10436bd15660b6d7e6fbef8364069983a688ffd5`이며, 이 커밋에서 Mac·Android 설치 파일을 빌드했다. 공개 설치 파일 3개를 다시 내려받아 로컬 원본 및 GitHub SHA-256 digest와 일치함을 확인했다. Mac ZIP의 내장 build-info와 plist, Android APK의 버전·build 23 및 기존 서명 인증서도 확인했다.
