# Open Deck 0.12.1 재연결 실기기 검증

Galaxy Tab S7(`SM-T870`, Android 13 / API 33)의 **Open Deck 0.12.1 / build 22**에서 저장 주소가 응답하지 않을 때 자동 검색으로 Wi-Fi 연결이 복구됨을 확인했다. 소스는 `7c4196fbdcb979a9571eaf69fed6653842bae02e`이며 Mac과 태블릿에 같은 버전을 설치했다. [검증 증거](evidence/0.12.1-physical.json)에 판정과 비공개 원본 해시를 기록한다. 실제 태블릿 재부팅 후 복구, 원래 연결 모드 복원, 공개 릴리즈 파일 확인까지 완료했다.

## 원래 장애와 구버전 재현

과거 기록에 비해 Mac IP는 바뀌었지만 인증서 fingerprint는 같았다. 현재 HTTPS health는 200이고 USB 연결 직후 현재 주소를 학습해 Wi-Fi 연결이 복구됐다. 최초 실패 저장 주소는 USB 학습 전에 확보하지 못했으므로 **IP 변경을 원래 장애의 확정 원인으로 단정하지 않는다.**

0.12.0에서 Wi-Fi 전용 모드의 저장 주소를 같은 Mac의 닫힌 포트로 바꾸고 앱을 재시작했다. 약 16초 관찰창의 0~14초 기록 8개가 모두 offline이었다. 이는 **실제 네트워크 IP를 강제로 바꾼 시험이 아니다.** 제한된 관찰 결과를 영구적인 복구 불가로 확대하지 않는다.

| 연결 기록의 자동 검색 시작 → 인증서 일치 호스트 → Wi-Fi 연결 | 모두 확인 |

| 태블릿 전체 재부팅·잠금 해제·앱 실행 후 자동 복구 | 통과, 앱 실행 후 5.03초에 연결 관측 |
| 태블릿 재부팅 후 기존 연결 기록 10개 유지 | 10/10 통과 |

6.06초와 5.03초는 각 통제 실행에서의 관측값이며 네트워크별 복구 시간을 보장하지 않는다. 실제 태블릿 재부팅 뒤 사용자가 잠금을 해제하고 실행 담당자가 ADB로 앱을 실행했을 때, 저장된 닫힌 포트 주소에서 자동 검색으로 Wi-Fi에 다시 연결됐다. 연결 기록에서도 첫 복구와 재부팅 후 복구의 자동 검색·인증서 확인 두 차례를 확인했다.

**부팅 시 앱 자동 실행을 검증한 것이 아니다.** USB 케이블은 조작·기록 수집용으로 유지했고, 앱은 Wi-Fi 전용 모드였으며 호스트에서 실제 Wi-Fi 데이터 경로를 확인했다. 재열거 중의 일시적인 ADB transport 실패와 최초 잠금 해제 전 OS의 앱 실행 거절은 재대기·직접 잠금 해제 후 진행한 검사 절차의 상태로 구분한다.

## 최종 상태와 공개 릴리즈

태블릿 연결 방식을 원래의 자동 모드로 복원했다. 수동 호스트 검색에서도 저장된 인증서와 일치하는 Mac을 찾아 선택했고, 검사 대화상자를 정리하기 위한 최종 앱 재실행 후 Wi-Fi 연결을 확인했다.

[GitHub v0.12.1 릴리즈](https://github.com/Yaklede/open-deck/releases/tag/v0.12.1)는 정식 최신 릴리즈로 게시됐다. 태그와 소스 커밋이 일치하며, APK·Mac ZIP·SHA256SUMS 3개 파일의 GitHub digest와 공개 다운로드 SHA-256이 모두 같다. Mac ZIP CRC와 내장 build-info도 통과했다.

공개 APK 서명 검증은 통과했고 기존 서명자 SHA-256 `15cfc6762d9b063abd2ce5b8cd665757f1e30b03707b921abb4619ff38aeba4a`를 유지했다. `SHA256SUMS.txt` 자체의 SHA-256은 `7599d61d8478cafba1cc364c88ab11c05fd8979b444d29d2b2f3d88599e22e2f`다.

원본 캡처, PIN·토큰, 기기 일련번호, 운영 설정과 사설 주소는 공개하지 않는다.
