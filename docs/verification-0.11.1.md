# Open Deck 0.11.1 그래프 터치·드래그 실기기 검증

Samsung SM-T870의 네이티브 Open Deck **0.11.1 / build 20**에서 Grafana 그래프 8개의 탭·가로 드래그를 검증했다. 총 **16/16개 제스처**에서 표시한 시각·값이 실제 측정 샘플과 일치했고, 터치한 시간에 가장 가까운 측정 지점이 선택됐다. 완료된 제스처에서 손을 뗀 뒤에도 선택이 유지됐다.

검증한 설치 앱의 소스 커밋은 `d432370b73485e64a40a7b499e4fde65a71a194b`다. 공개 [검증 결과 JSON](evidence/0.11.1-physical.json)은 판정·검증 방법·원본 63개 파일의 SHA-256만 포함하며, 최종 GitHub 게시 파일의 커밋·서명·설치 상태와 체크섬도 아래에서 확인했다.

## 범위와 결과

| Grafana 그래프 | 탭 | 가로 드래그 | 실제 샘플·가장 가까운 지점·UP 후 유지 |
| --- | --- | --- | --- |
| 시스템 CPU | 통과 | 통과 | 모두 통과 |
| 평균 응답시간 | 통과 | 통과 | 모두 통과 |
| 5xx 오류율 | 통과 | 통과 | 모두 통과 |
| RPS | 통과 | 통과 | 모두 통과 |
| DB TPS | 통과 | 통과 | 모두 통과 |
| DB QPS | 통과 | 통과 | 모두 통과 |
| DB CPU | 통과 | 통과 | 모두 통과 |
| DB 메모리 | 통과 | 통과 | 모두 통과 |

각 그래프의 탭과 드래그는 서로 다른 시각을 선택했다. 제스처 완료 후의 native XML 접근성 설명에 나타난 선택 시각·포맷된 값을 수집 전후 원본 샘플 배열과 대조하고, 그래프 좌표에서 계산한 목표 시간의 가장 가까운 실측 지점인지 확인했다. 실제 터치와 손을 떼는 조작은 실행 담당자의 기록이며, 문서 작성 단계에서는 저장된 원본을 읽기 전용으로 재검증했다.

그래프 탭 8개를 선택할 때 이전 선택이 해제되는 assertion도 모두 통과했다. 이 항목은 실행 담당자의 자동 조작 기록을 인용한다. 원본 샘플 시각이 없는 **내 Mac의 별도 로컬 이력 그래프는 이번 계약 범위에 포함하지 않는다.**

## 시각 검토와 설정 보존

시스템 CPU와 평균 응답시간의 탭·드래그 화면 4장 및 DB 그래프 4개의 드래그 화면은 독립 검토자가 확인했다. 실행 담당자는 시스템 CPU 드래그와 DB 메모리 드래그 화면도 직접 검토했다. CPU가 먼저 읽히는 기존 정보 위계를 유지했다. 이 시각 검토를 모든 16개 화면의 별도 시각 검토로 확대해 주장하지 않는다.

비공개 보존 검사에서 운영 덱·페어링 기기·태블릿별 설정은 모두 원래 상태와 같았다. 설치된 APK가 현재 `dist/Open-Deck-Android.apk`와 일치한다는 검사 결과를 확인했고, 배포 폴더 APK 해시도 읽기 전용으로 대조했다. 이 결과는 최종 GitHub 게시 파일의 동일성 검사를 대신하지 않는다.

실제 지표 수치, 샘플 시각, 프로젝트·호스트명, 기기 일련번호, 토큰, 원본 PNG/XML과 샘플 배열은 공개하지 않는다. 각 원본은 공개 JSON의 파일명과 SHA-256으로만 식별한다.

## 추가 터치 생명주기 검증

완료된 16개 제스처와 별도로 아래 **4/4개 항목**을 확인했다.

| 추가 항목 | 결과 | 근거 |
| --- | --- | --- |
| UP 없이 ACTION_DOWN을 유지하는 동안 선택 표시 | 통과 | native XML과 실행 담당자의 입력 주입 기록 |
| 손을 놓기 전 ACTION_MOVE에서 선택 시각·값 변경 | 통과 | DOWN/MOVE의 비공개 선택 설명 비교 |
| ACTION_CANCEL 후 선택 해제 | 통과 | 선택 설명 부재와 기본 최고점 복귀 관찰 |
| 실제 데이터 갱신 후 선택 시각 유지 | 통과 | 원본 시계열 변경 및 전후 선택 시각 비교 |

입력 주입 순서는 실행 담당자의 기록이다. XML에서는 DOWN과 MOVE의 선택 설명이 서로 다르고, CANCEL 뒤에는 선택 설명이 없는 것을 확인했다. 기본 최고점 표시로 복귀한 사실은 실행 담당자의 직접 관찰로 구분했다. 새 수집 데이터 검증에서는 시스템 시계열 배열이 실제로 바뀐 동안 선택 시각은 같았다.

## 제한된 성능 관찰

시스템 CPU 상세 화면 하나에서 `gfxinfo`를 초기화한 뒤 900ms 가로 스와이프 8회를 실행했다. 기록된 274개 렌더링 프레임의 UI 프레임 시간은 중앙값 5ms·95백분위 10ms·99백분위 11ms였다. 테스트 조건은 실행 담당자 기록이며 수치는 비공개 `gfxinfo` 원본에서 확인했다.

이는 해당 실기기의 한 측정 구간에 한정된 참고 관찰이다. 이전 버전과의 비교나 성능 개선율, 전체 앱·모든 그래프의 성능 보장을 주장하지 않는다. 원본 로그는 공개하지 않는다.
