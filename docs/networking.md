# 연결과 자동 복구

Open Deck은 최초 USB 등록으로 Mac의 인증서와 기기별 인증 정보를 저장한다. 등록 후에는 같은 사설 네트워크의 HTTPS 연결을 사용할 수 있다. 기본 포트는 Mac 편집기·USB가 `127.0.0.1:8840`, 암호화 Wi-Fi가 `8841`이며 Wi-Fi 포트는 Mac 설정에서 바꿀 수 있다.

## Mac 주소가 바뀌었을 때

0.12.1은 앱이 화면에 열린 상태에서 저장된 주소 연결이 두 번 실패하면 같은 네트워크의 Mac을 자동으로 다시 검색한다. Mac은 DNS-SD/mDNS의 `_opendeck._tcp` 서비스를 알리고 Android 앱은 NSD로 주소를 찾는다. 새 주소를 발견해도 USB 등록 때 저장한 인증서와 일치하는 HTTPS 연결인지 확인한 뒤 사용한다. 기존 기기 인증 정보를 유지하므로 IP 변경만으로 페어링을 새로 만들 필요는 없다.

검색은 한 번에 10초 동안 진행하며, 실패하면 15초·30초·최대 60초 간격으로 다시 시도한다. 자동 검색은 **자동** 또는 **Wi-Fi 전용** 연결 방식에서 사용한다. **USB 전용**은 USB 연결을 유지한다. Mac 앱이 실행 중이고 Mac의 네트워크 설정에서 호스트 검색이 켜져 있어야 한다. 자동 호스트 검색은 앱이 화면에 열린 동안 수행한다. 태블릿 부팅 시 앱을 자동으로 실행하는 기능은 이번 변경에 포함하지 않는다.

## 검색이 되지 않을 때

- 두 기기가 서로 접근할 수 있는 같은 네트워크인지 확인한다. 게스트 네트워크의 기기 격리나 멀티캐스트 차단은 자동 검색을 막을 수 있다.
- Mac Open Deck의 Wi-Fi 연결과 호스트 검색 설정을 확인한다. 방화벽에서 설정한 HTTPS 포트의 접근이 허용되어야 한다.
- 태블릿 **연결 방식 · Wi-Fi / USB → 맥 Wi-Fi 주소 관리**에서 현재 Mac의 HTTPS 주소를 직접 추가할 수 있다. 수동 주소도 저장된 인증서 검증을 통과해야 한다.
- USB를 다시 연결하면 인증된 로컬 연결을 통해 현재 네트워크 주소를 갱신할 수 있다.

## 연결 상태와 데이터 시각

0.12.2부터 호스트는 지표 갱신과 별개로 2초 간격의 연결 확인 신호를 보낸다. Android는 이 신호를 포함한 스트림 수신 여부로 연결을 판단하고, 마지막 상태 데이터의 수신 시각은 별도로 확인한다. 데이터가 8초 이상 갱신되지 않으면 이전 데이터로 취급하지만, 연결 확인 신호가 도착하는 소켓을 데이터 지연만으로 끊지는 않는다. 스트림 수신 자체가 20초 동안 멈추면 재연결한다.

전송이 밀리는 동안 호스트는 상태를 계속 쌓지 않고 가장 최근 상태 하나를 대기시킨다. 전송이 재개되면 최신 상태를 보낸다. 설정 변경과 기기 권한 확인은 이 과정에서도 유지한다. 짧은 연결이 반복되면 Android 재시도 간격은 1초부터 최대 15초까지 늘어난다. HTTP 응답 헤더만 받거나 상태 한 번만 받고 끊기는 연결은 안정적인 복구로 보지 않는다.

자동 연결에서 USB로 동작 중이면 Wi-Fi 주소를 검증한 뒤 해당 주소로 전환한다. 네트워크 주소를 새로 배웠다는 이유만으로 USB 연결을 끊지는 않는다. Wi-Fi 전환 시도 사이에는 30초 간격을 두며, USB 전용 설정은 그대로 따른다.

인증서를 새로 만들거나 직접 교체한 경우에는 IP 변경과 다르다. 자동 검색이나 수동 주소 추가만으로 새 인증서를 신뢰하지 않으며, USB 연결을 통해 변경된 인증서를 등록해야 한다. 공유기의 공인 포트를 열 필요는 없다.

## 보안 경계

검색으로 받은 서비스 이름·IP는 신뢰의 근거가 아니다. 자동 복구는 기존 인증서 pin 및 유효기간을 검증하는 HTTPS 연결을 사용한다. 다른 Mac의 인증서, 만료된 인증서, 평문 HTTP 광고는 자동 복구 대상으로 채택하지 않는다. LAN에서는 태블릿용 API만 제공하고 편집기와 관리자 API는 차단한다.

이 문서는 연결 동작과 요구 조건을 설명한다. 실제 기기·에뮬레이터별 검사 결과와 배포 파일 확인은 해당 버전의 검증 보고서에 별도로 기록한다.
