# 계정·복구·암호화 백업 검증

이 문서는 0.10.0의 보안 설정 구현과 실제 검증 위치를 연결합니다. 테스트는 임시 디렉터리의 합성 계정과 localhost 서버에서 실행하며, 실제 사용자의 계정·암호·복구 키를 생성하거나 교체하지 않습니다.

| 설정 | 저장·실행 동작 | 검증 |
| --- | --- | --- |
| 관리자 계정 | `account.json`에 사용자명, scrypt 암호 검증값 저장. 네이티브 부트스트랩 토큰만으로는 계정 설정 후 편집 API를 사용할 수 없음 | `test/account-api.test.mjs`: 관리자 API·스냅샷·실행 API의 401 및 로그인 후 200 |
| 로그인 세션 | 난수 토큰의 SHA-256 해시만 저장. HttpOnly/SameSite=Strict 쿠키, 1~720시간 수명, 최대 32개 세션 | `test/account-vault.test.mjs`: 재시작·만료·해시 저장; API 테스트: 쿠키·세션 목록 |
| 세션 종료 | 현재/개별/전체 세션 해제. 무효화된 편집기 이벤트 스트림 종료 | API 테스트: 개별 세션 차단 및 해당 SSE 종료, 태블릿 SSE·스냅샷 유지 |
| 계정 정보 변경 | 현재 암호로 사용자명·암호·세션 수명 변경. 암호 변경 시 다른 세션 해제 | 단위 테스트: 잘못된 현재 암호 차단, 새 사용자명과 암호 로그인 |
| 계정 복구 키 | 생성 직후 한 번 표시. 별도 보관 확인 후 활성화. scrypt 검증값만 저장. 교체·분실·사용 완료 상태 보존 | 단위 테스트: 미확인 키 거부, 이전 키 무효, 단일 사용, 분실 상태 재시작 보존 |
| 계정 복구 | 복구 키와 사용자명으로 새 암호 설정. 기존 세션·사용한 키 무효화. 기존 편집기 잠금 암호도 동기화 | API 테스트: 복구 후 로그인, 새 암호로 잠금 해제, 이전 키 재사용 거부 |
| 암호화 비밀 저장소 | 무작위 AES-256 키를 암호 기반 scrypt 키로 감싸 저장. 해제된 마스터 키는 메모리에만 유지 | 단위 테스트: 파일에 암호·마스터 키·비밀 값 평문 없음, 재시작 시 잠김 |
| 비밀 저장·사용 | 추가·교체·삭제, 메타데이터만 UI/API 반환. HTTP 연결의 `secretId`와 일치하는 값 사용. 기존 Keychain 연결은 유지 | API 테스트: 값 비노출, 잠긴 저장소에서 비밀 접근 차단; `host/connectors.mjs`와 서버의 secret resolver |
| 백업 복구 키 | 별도 생성·보관 확인·교체·분실 표시. 암호를 잊으면 키로 저장소 암호 재설정 | 단위 테스트: 교체 전 키 거부, 새 키 복구, 사용한 키 무효 |
| 로컬 백업 암호화 | 선택적으로 AES-256-GCM 적용. 복구 키 보관 확인 필요. 잠김 상태에서 평문 백업으로 우회하지 않음 | 단위·API 테스트: 암호화 파일·메타데이터, 잠긴 수동/예약 백업 423 `VAULT_LOCKED` |
| 기존 백업 변환 | 평문 백업을 모두 검증한 뒤 파일별 원자적 교체. 기존 평문 형식 읽기 호환 유지 | 단위 테스트: 기존 파일 변환 후 내용 복원, 평문 민감 문자열 부재 |
| 암호화 내보내기 | 별도 암호 방식과 복구 키 방식 제공. 다른 설치에서도 해당 복구 키로 가져오기 가능 | 단위 테스트: 새 저장소 인스턴스에서 복호화, 변조·틀린 키 거부 |
| 로그인 보호 | 1분 내 5회 실패 후 제한. 시크릿 파일 0600, 심볼릭 링크 거부 | 단위 테스트: 429 제한·시간 경과 후 재시도·권한·심볼릭 링크 |
| 진단 기록 | 계정·저장소 작업 종류만 기록. 암호·복구 키·비밀 값은 기록하지 않음 | API 테스트: 진단 응답에 입력한 암호·복구 키 없음 |

검증 명령:

```sh
node --test test/account-vault.test.mjs test/backups.test.mjs test/editor-lock.test.mjs
node --test test/account-api.test.mjs
```

첫 명령 28개, 두 번째 명령 4개 테스트가 통과했습니다. 두 번째 명령은 임시 localhost 포트에서 실제 HTTP 요청과 SSE 스트림을 검사합니다.

별도 헤드리스 Chrome에서 합성 계정을 실제 설정 화면으로 생성했습니다. 복구 키 생성 → 파일 다운로드 → 보관한 키 재입력 확인, 저장소 생성, 비밀 추가, 기존 백업 암호화, 수동 암호화 백업, 전체 로그아웃 후 재로그인까지 확인했습니다. 재로그인 직전의 오래된 401 응답이 로그인 창을 다시 여는 경합도 이 과정에서 수정하고 재검증했습니다. 최종 UI 실행의 브라우저 오류는 0건입니다.

화면에는 합성 계정 이름과 비밀의 식별자만 표시되며 암호, 복구 키와 비밀 값은 포함하지 않습니다.

암호화 저장소는 앱을 다시 시작하면 잠깁니다. 해제 전에는 해당 비밀을 사용하는 연결과 암호화 예약 백업을 실행하지 않습니다. 이미 외부로 내보낸 백업에는 내보낸 시점의 복구 키가 필요하므로 키를 교체한 뒤 중요한 백업을 다시 내보내도록 화면에서 안내합니다. 계정 인증 파일, 태블릿 페어링 토큰과 기존 Mac Keychain 비밀은 일반 백업에 포함하지 않습니다.

한국어 원문을 제외한 18개 언어의 신규 보안 UI 89개 문구를 `host/public/locales/manual-security.json`에 직접 번역했습니다. 총 1,602개 번역의 키 수와 `{0}` 자리표시자를 검사했으며, 이 신규 문구를 외부 번역 서비스에 전송하지 않았습니다.
